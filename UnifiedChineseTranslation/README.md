# 本地模组统一汉化

游戏只需启用一个新增补全模组，内部按 `Modules/<上游模组>/` 区分汉化来源。人工译文源为 `Reviewed/<上游模组>.json`，运行 `Tools/Generate.ps1` 生成对应模块的语言文件；迁入的GlitterNet和虫灾资产直接在其模块目录维护。不要单独编辑生成文件后又重新生成，否则会被映射覆盖。目录映射和检查状态见 `Modules/index.json`。条件加载由 `LoadFolders.xml` 管理。放在全部内容模组与已有汉化之后。

## 使用

启用“本地模组统一汉化 / Unified Chinese Translation”，停用独立的“GlitterNet 简体中文补全与校正”和“Custom Infestations (Continued) - 简体中文补丁”。保留GlitterNet、自定义虫灾及XML Extensions上游模组。其他已有社区汉化也保留：本整合包只补缺漏，不打包替代它们。

启用相应上游时才加载模块语言文件；未安装上游时不会注入它的Def。GlitterNet的局部开发按钮补丁只在它的程序集存在时应用，不修改玩法。

## 检查边界

`Tools/Audit.ps1` 读取当前实际启用列表、版本加载目录和全部启用中文补丁，报告未译候选；识别中文目录别名并排除纯规则变量。报告保存在 `game-data/rimworld/reports/unified-translation-audit/`，不将上游全文快照或个人游戏配置上传Git。

静态扫描不等于所有条目确实漏译。专有名称、内部规则、跨模组动态字段、硬编码文字、语言存档和XML补丁需要人工复核。只对确认的玩家可见内容提交译文，保留占位符、标签、数值及规则左侧。不得用逐词替换或未审核的机器翻译标记任务完成。

初始扫描156个启用项目，包括游戏/DLC与汉化项目。已解析全部来源；阶段性覆盖数及剩余候选以实际报告为准。每批复核后更新索引并重新检查，不把“存在中文文件”视为完整汉化。

首轮静态补齐：61个模块；扫描范围内未处理英文候选和未处理变量/规则差异均为0，16项英文保留决策已记录。该结论仅覆盖已成功解析的XML/Keyed及指定可见字段，不包括所有继承字段、运行时生成内容和全部C#硬编码。已有中文全文的语义也不由自动检查证明；人工复核确认的问题已覆盖修正。详见 `VALIDATION.md`。

Glitter Tech原汉化有一个无法解析的XML文件，Follow Me及Oracle重贴图的版本加载配置需进一步运行核对；不能把这些项目标为已完整验证。整合包不直接改这些上游文件。

## 版本管理与回退

### 0.1.4 校验语义修正与Harmony审计

修正0.1.3的校验误判：SetDefFieldAtPath的返回值表示是否实际注入，placeholder验证时即使有效也可能返回false；现在以临时校验对象的错误列表是否为空判断，不再因此停用有效译文。新回归测试刻意模拟“有效路径返回false且无错误”。MarkThatPawn之外的语言目录不再包装，进一步缩小兼容层范围。

本包未捆绑0Harmony.dll，仅引用现有Harmony 2.4.3。新增只读启动审计，记录实际加载的所有Harmony版本、路径及本包六个补丁目标的其他补丁所有者（包括其他已加载版本）；不加载额外DLL，不替换Harmony，不修改HAR/Mid-saver。补丁冲突仍可能发生，不能将“无捆绑DLL”当作“绝无冲突”。妖怪村仍排除。下一次启动报告才能确认实际恢复与迁移数量。

### 0.1.3 非妖怪村旧汉化适配

用户明确排除妖怪村额外汉化：不加载Modules/YokaiVillage，不处理妖怪村自带译文的错误；旧译文源留在Git中以便恢复，游戏内妖怪村与自带汉化保持原样。

其他模组的已审核错误登记在Repairs/KnownErrors.xml（483个字段条目）。语言注入前调用游戏字段检查的isPlaceholder=true只验证路径，不改变Def值；可验证的旧蓝图/框架名称迁移到当前名称，已有有效译文优先；确实不存在或路径不适用的旧译文不再尝试注入，原文件仍保留。每项迁移与停用均写入启动诊断，未登记的新错误保持原生报告，不清空错误列表。只有MarkThatPawn旧MarkerDef目录在虚拟语言目录中改为完整类型名，Workshop和原版语言文件均不改写、不打包进仓库。

隐含定义缺失检查延后到游戏生成隐含定义之后，不因早期尚未生成就停用有效译文。实际生效数量须查看下次启动报告。停用此包即可取消此兼容层；不写存档或游戏配置。

### 0.1.2 运行时路径修正

依据实际0.1.1启动报告，逐项修正188个未注入路径：103项数字索引改为游戏已确认的规范句柄，73项GlitterNet任务文本追加`.slateRef`，9项Polaris使用按钮采用真实compClass句柄，1项妖怪村场景文本使用GameStartDialog句柄；Complex Jobs的44项设置文本统一改为作者提供的Keyed tKey（包括2项已越界路径），不再依赖可能删减的条件列表索引。总计230项路径/类别修正，译文内容与变量保持不变。

`PathCorrections.json`是可复现的修正表。人工译文映射保留原始XML定位键，Generate在验证原文后输出修正的运行时键；迁入的GlitterNet任务文件也按此表修正。Validate检查新键存在、旧键消失及迁入译文完全保留。ImportRuntimeCorrections工具仅用于导入已审核的本地启动报告，不会自动读取日志或改变上游模组。

此版本尚未经过真实游戏重启，不能声称全局1014项错误清零或已解决原生崩溃。其他模组自带汉化的错误不在本次修改范围。

### 0.1.1 加载诊断修正

补齐Harmony依赖链接。本包自己的简体中文语言文件覆盖已有同名键时，先移交该精确键，再由原生加载器插入新译文；只在本包 `Modules/*/Languages/ChineseSimplified/` 路径内生效，不全局忽略重复键，不清除错误列表。真正的字段类型、禁止翻译标记、列表越界及XML错误仍由游戏检查。同文件重复Keyed键与损坏XML不执行移交。

每次启动结束后自动导出带唯一名称的翻译诊断到 `D:/learn/openCode/content/game-data/rimworld/reports/unified-translation-runtime/`，包含有意覆盖清单、所有模组的语言错误和本包未成功注入的字段。不读写存档，不改变游戏机制。日志中的1014项是旧版本整套语言数据汇总，尚不能认定新版全部消除；请以单实例重启后的报告为准。

运行 `Tools/TestLoading.ps1` 可执行覆盖范围及异常输入的替身测试；它不等同真实游戏验证。

仅Git管理，不另建模组备份。逐批提交并同步用户GitHub仓库。禁用整合包可回退；旧独立汉化源码仍保留，不删除。未修改存档。尚未确认发布许可，不创建发行版或Workshop项目。
